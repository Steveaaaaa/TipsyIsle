# 柏宝书与剧情分支兼容方案

状态：兼容层已实现，玩家验收待进行。本专项以原版 [柏宝书 1.3.5（`0a3a1cd`）](https://github.com/baibai-git/ST-BaiBai-Book/tree/0a3a1cdfe92bf5ff1b822b6b6588cb694090d0da) 为验收基线，延续[酒馆扩展兼容总方案](./SILLYTAVERN_EXTENSION_COMPAT_PLAN.zh-CN.md)中步骤 1、3、5。网页、Windows 和 Android 用同一套兼容行为。每一步开始前重读本方案，完成后记录实际改动、验证结果和下一步，开发验证与玩家验收分开记录。

## 玩家应该看到什么

第 20 楼之前，你和角色一起进了旅店；之后 A 线拿到了钥匙，B 线没有。两条线可以继承分叉前已经保存的记忆。之后在 A 线获得、修改或删除的记忆，只影响 A。切到 B 时，柏宝书面板和下一轮喂给模型的记忆都以 B 为准；切回 A、关掉应用再打开，A 的记忆仍在。只有主动用「带记忆开新聊天」才跨会话带走选中的记忆。

| 场景 | 约定 |
| --- | --- |
| 切换已经存在的路线、翻选不同回复 | 恢复目标路线已保存的楼层摘要、压缩摘要、隐藏状态和记忆注入；没有保存过的地方保持空白。 |
| 从旧楼重新选择 | 从该分叉点的选择前快照继承，到分叉点为止；原路线后来新增的剧情和对旧楼的修改不倒灌。 |
| 分叉后回头补摘共同楼层 | 正文仍可共享；这次补摘、改摘要、删摘要、隐藏或取消隐藏只在当前路线生效。 |
| 编辑、删楼、重新生成 | 按现有剧情操作语义处理正文。删除或替换的楼层不能继续作为有效记忆被注入或召回；失败回滚后继续使用原先的记忆。对原地编辑导致过时的摘要，沿用插件的手动重摘习惯，但在重新确认前不拿过时内容做向量召回。 |
| 切线时仍有旧任务 | 已经算完、尚在等待保存的改动先落到旧路线。仍在生成的任务继续遵守现有忙碌状态；已失效的返回不能写入新路线。 |
| 向量服务不可用 | 只允许使用同样按路线隔离的本地降级；降级也不可用时，本轮不做向量召回，普通摘要和聊天照常。 |

## 1. 让普通摘要跟着路线保存和恢复

- [ ] **统一路线身份。** 内部增加一个由宿主解析的路线地址，含 `chatId`、稳定 `routeId` 和当前绑定的 `branchEpoch`。复用 [`activeAddress`](../src/plugins/native/route-graph.ts) 和已有路线锚点。`routeId` 用来找已经保存的记忆；`branchEpoch` 用来拒绝旧请求，切回同一条路线仍能找到原来的记忆。普通追加、流式占位和重启不换路线地址。审清 `retryStoryFrom`、故事地图选线、回复翻页、编辑旧楼时的分叉，以及重生成临时退回父楼、失败还原的行为。重生成准备开始前捕获原路线地址，获取的记忆仍要以实际参与本轮生成的楼层为限；预览只读。保持插件可见的 `getCurrentChatId()` 和酒馆事件参数不变。
- [ ] **把插件数据放回正确的层级。** 在兼容层集中声明柏宝书需要随路线保存的消息字段（基线至少包括 `bbs_leaf`、`bbs_hidden`、`bbs_omit`，核对内部提示标记和正文旁注如何一起保存），核心只处理通用的扩展消息附加数据、路线快照和增量，不判断插件名或 `bbs_*`。已有 `chatMetadata` 检查点继续承载 `baibai_book` 压缩摘要、隐藏状态和 bundle 引用；通用消息附加数据按稳定的 `messageId + swipeId` 存稀疏改动，删除用明确标记，不能又从旧 `extra` 回填。让分叉点和恢复点引用各自的不可变版本；按现有消息变量快照做法复用未变块，只投影当前路径的条目。原生正文及其他扩展字段仍走原有接口。核对 `bbs_items`、`bbs_vars` 等正文旁注是否会通过 `saveChat()` 改到共享楼层；需要隔离时和附加数据同批写入，由兼容层按路线投影给阅读和模型，避免为旁注复制整楼或改写共同正文。
- [ ] **保存增量与回滚。** 扩展写回带发起时的路线绑定、消息 ID、回复版本和正文基线。先核对目标，再原子提交 `extra`／旁注、`chatMetadata`、隐藏状态及当前检查点；不能只存一半。分叉从选择前版本继承；普通切线恢复最新的路线版本。按上游 `childIds` 语义核对压缩摘要：活跃路线还原后若引用已删除、已替换或不属于本线的叶子，由兼容适配处理失效节点，不把跨越分支点的整段旧摘要继续注入。失败重生成恢复原回复及原记忆，不把临时回退、预览或失败候选落成另一条线的状态。
- [ ] **切线前收住已完成的写入。** 为现有兼容通信加一次有界的切换前提交：在旧 iframe 和旧分支绑定仍有效时，提取已改但没发出的聊天增量，复用 `saveChatMetadata` 和现有写入队列；等到本地保存完成再调用 `rememberBranch`、选线和重建运行环境。这个提交不发聊天事件、不启动模型，也不等待不相关的后台任务。没有兼容页面或没有改动时直接切换；保存失败就留在当前路线并通过现有通知提示重试。宿主发起和 iframe 发起的切线都进同一条协调路径；后者不能在等自己处理的 RPC 时又等旧命令队列，使用独立的提交往返或由原调用携带增量。切过去后先装载目标快照，再触发原有 `CHAT_CHANGED` 初始化；收集本轮注入前等待目标路线记忆就绪，避免拿到旧注入或只有半份数据。普通切线不尝试复用旧扩展实例。
- [ ] **兼容已有档。** 首次读取无新记录的旧档，用可确认属于当前消息及回复版本的已存数据作为基线；历史共用楼层的数据若已被覆盖、无法确定归属，不推断它原来在哪条路线。保留原始记录，避免把来源不明的向量或压缩摘要当成已验证的分支数据；可用的楼层摘要继续读取，缺的允许玩家补摘。检查本地存档重启、归档恢复与 `.tipsy-story` 的导入导出：正常的路线记忆一并保存，导入副本按宿主已有规则重映射消息/回复标识，派生索引不跟档搬。新存储字段由旧档可选读取，不做启动时的全库迁移。

完成标准：关掉向量召回，也能在 A/B 之间来回切；分别补摘同一条旧消息时两边不同；关软件后各自恢复；切线前已完成但待保存的摘要不会丢，迟到结果不能写进别的路线。

## 2. 把向量索引、召回缓存和降级路径对齐

- [ ] **请求绑定在发起时确定。** 兼容通信受理请求时捕获不可变的路线地址和请求所属的记忆版本，在 `workspace-host.ts` 懒加载向量模块之前就确定。`chat:<id>` 仍按上游协议返回，在宿主内部转换成「角色、库、会话、路线」。`reconcile`、清理、写入、读、查询都只操作捕获的集合；工作线程不得等到真正执行时再读“当前路线”。路线切换后拒收旧结果；同一路线内容被改过时，也不能把旧版本的查询或写入当成新版本，处理查询、对账、删除之间的时序。用路线切换前后的记忆版本保护可见性：旧向量没来得及清理时，查询也不得返回失效叶子；同一事务内处理对应的向量与正文记录。
- [ ] **隔离插件实际读的缓存。** 在扩展代码加载前，由兼容层为基准版的 `bbs_vec_recall_cache` 建有界的路线缓存，匹配同一角色、会话、路线及可复用的记忆版本；其他 `localStorage` 键、插件全局配置和角色脚本行为沿用原规则。延续上游对同一路线近期输入和模型配置的缓存判定；摘要改动、隐藏范围或有效 bundle 变化，以及影响命中的索引清理，需要使旧缓存失效。已有无路线标记的缓存不再读取；旧文档的异步回调不能换一个新路线的缓存去写。缓存无法保存时按无缓存运行，不牵连聊天。
- [ ] **处理真实的本地降级。** 柏宝书探测 `/status` 失败会改用 `bbs_vec_local`，仅替换 HTTP scope 无效。在兼容环境内只对这个已知数据库名按稳定路线地址映射，正常返回 `IDBOpenDBRequest` 等原生接口；不碰其他数据库或网站存储，不重用旧的未分线索引。要覆盖 `open`、清理及该版实际使用的入口。换线时关闭旧运行环境的访问；若某端没法保持隔离，明确让这条向量路径失败并留下诊断，按插件既有行为降级成不召回。不得把宿主向量失败伪装成成功。
- [ ] **控制开销。** 切线只切快照及集合地址，不请求模型、不批量复制或扫描整个索引。新路线启用向量时由现有对账按需建立索引；已有路线复用仍有效的条目，同一条路线只改正文或时间时只更新 payload。保持现有 Worker；对账和索引清理按实际改动进行，切线不做全库维护。跨分支复用向量不是首批条件，将来若做只能复用确认内容相同的记录，不能把 A 的索引整组复制到 B。普通发送维持原来的调用次数，缓存未命中时才走柏宝书已配置的向量流程。

完成标准：用相同末尾楼层和相同输入走 A、B，不能复用对方的召回；清空 B 的索引后 A 保持可用。无宿主向量服务时，同样满足隔离或明确跳过向量召回。反复切回未改动的同一路线不触发整库重建。

## 3. 验证「带记忆开新聊天」和交付边界

- [ ] **冻结来源路线。** 顺着[上游搬运流程](https://github.com/baibai-git/ST-BaiBai-Book/blob/0a3a1cdfe92bf5ff1b822b6b6588cb694090d0da/src/memory/carryover.ts)核对它先请求 bundle、再保存并调用 `doNewChat()` 的顺序。创建 bundle 时只能读当前源路线的有效索引视图；资料刷新滞后时允许普通种子摘要继续搬运，不拿不存在或已失效的向量凑数。只把显式继承且当前路线确实持有的 bundle 加入召回；源路线之后改删不会改变已冻结的内容。核对宿主索引不可用时，原版的本地模式没有 bundle 能力，应继续搬普通摘要，说明向量未继承。
- [ ] **保留一次性新会话交接。** 保留已有「原脚本能在 `await doNewChat()` 后写开场」的约定。把来源地址、目标地址、权限和生命周期分开：旧 RPC 与召回结果带旧身份，交接期间只允许新开场提交及其必要读写；普通后台任务、缓存和本地索引不能拿到新路线的地址。目标开场与 metadata 提交并确认后，新绑定才能开始使用目标缓存；核对 `reloadCurrentChat()` 和 `CHAT_CHANGED`，不重复插楼、不提前卸载搬运调用。交接失败保留源会话和已有路线，使用现有错误入口说明新聊没有完整继承。
- [ ] **记录交付。** 文档记录支持的柏宝书提交、平台和不纳入的功能：不扩张到龙血玄黄、不加新的记忆模式、不改柏宝书包及核心插件 SDK。维护者做源码核对、类型检查和构建，不新增测试用例、不跑性能基准或调用真实模型。确认网页及 Windows／Android 构建后，给玩家下面几条验收路径；结果按平台记录，不把打包成功写成实机已通过。

## 玩家验收清单

| 操作 | 应看到的结果 |
| --- | --- |
| 从同一楼分 A、B；A 拿钥匙，B 没拿。在 A、B 分别对共同旧楼补摘不同文字 | 共用正文还在；分支各自保留补摘结果，面板、普通提示词都没有另一条线的钥匙情节。 |
| 在 A 刚做完手动补摘、尚在延迟保存时切 B，再回 A；重启一次 | B 没收到该摘要，回 A 和重启后仍能找到。如果不能完成保存，本次留在 A 并有明确提示。 |
| 翻回复、重生成并停止，再删楼、切回旧线 | 取消重生成恢复原记忆；被替换或删除的内容不再进入本线提示词和召回，另一条线保留自己的数据。 |
| 开向量，让 A、B 最近两句内容一样，先 A 后 B；在 B 清索引；再模拟向量服务不可用 | B 不复用 A 的召回；清的是 B，A 仍可查。降级也不会串线。 |
| 在 B 使用「带记忆开新聊天」；之后回 B 修改摘要并进新聊再次召回 | 新聊只带 B 当时选中的材料；源路线之后的更新不改动已继承的快照。 |

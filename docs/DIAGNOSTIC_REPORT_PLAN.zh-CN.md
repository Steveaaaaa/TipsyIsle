# 错误日志与一键导出

状态：首版已实现。适用 Windows、Android 和网页版；真机功能验收待进行。

玩家遇到问题，打开「设置 → 高级与诊断 → 错误日志」，就能查看最近的记录，或点「导出诊断日志」把报告发给我们。报告要让我们看懂三件事：**是什么环境、装了哪些插件、操作失败在哪一步。**

## 导出内容

| 内容 | 记录什么 |
| --- | --- |
| 运行环境 | TipsyIsle 版本、Windows／Android／网页、能直接拿到的系统和浏览器或 WebView 版本、运行方式（原生／本地网关／纯浏览器）。 |
| 当前插件和脚本 | 原生插件、酒馆扩展、全局／预设／角色卡脚本分开列。记录名称、版本（有就写）、是否启用，以及宿主观察到的运行状态。已启用不等于加载成功，没观察到就写「未知」。 |
| 最近的故障和操作 | 时间、模块、操作、失败阶段、错误码或简短原因，有的话附 HTTP 状态和耗时。插件出错时把它的名称、版本和失败阶段直接记在那条日志里，停用或卸载后仍能看见这条记录。 |

例如：`Android · 启动检查更新 · 原生请求 api.github.com · 5 秒后超时`。如果请求成功，也要能区分「没有新版」「发现新版但用户忽略」「找到新版但缺少安卓包」。没有证据时不猜是不是代理问题。

## 怎么做

1. **记录。** 做一个共用的记录入口。首版覆盖启动与更新、模型列表与生成、素材导入和本地保存、扩展与脚本加载、原生插件报错。更新检查等跨层操作用一个编号串起开始、关键步骤和结果；原生端或网关在现有调用里带回必要的错误详情，由前端统一记录。更新检查先接通，插件和脚本复用已有诊断入口。只记关键步骤，不逐字记录生成内容。
2. **保存。** 用独立的本地日志键保留最近 500 条，上限 512 KiB，超出就清掉最旧的；小批量写入，失败记录尽快保存。首版复用应用内的本地存储，无需为了日志另建数据库或服务。存储不可用时先保留本次运行的记录，不影响聊天和更新。只写排障需要的字段，API 密钥、聊天内容和完整请求体不进日志。
3. **查看和导出。** 页面显示最近的事件，点开看详情；提供「导出诊断日志」和「清空日志」。用现有文件导出入口，Windows 和 Android 走系统保存，网页走浏览器下载。导出一个可直接打开的 `.txt`，按「环境 → 当前插件和脚本 → 最近记录」排列。无需 SHA、历史快照库、单独预览页或逐项勾选。

## 做完怎么看

- 安卓自动检查更新失败后，重启仍能导出，能分清有没有发请求、失败在哪一步。
- 某个酒馆扩展加载失败后，即使玩家停用它，报告仍保留当时的失败；当前清单则显示已停用。
- Windows、Android 和网页都能导出同样布局的报告。模型请求失败有线索可查，日志本身写不进去也不影响主功能。

## 实施记录

- 已接入启动、更新、模型列表、生成、素材和存档导入、本地保存失败、兼容扩展与脚本、原生插件故障。更新检查记录候选版本、HTTP 状态及失败阶段；找到了新版却缺本机安装包时保留候选版本。
- 日志独立存储，保留最近 500 条且不超过 512 KiB。当前插件清单与历史故障分别生成，停用或卸载不清除旧记录。
- 设置中可展开记录、清空或导出；错误通知也可直接打开导出说明，确认后保存。三端共用 UTF-8 文本格式和现有导出入口。
- 已通过 TypeScript 类型检查、网页版构建、Windows Rust 编译检查和 `git diff --check`。未新增或运行功能测试；Android 更新失败后重启、系统保存以及插件停用前后的导出留待实测。

# TipsyIsle 工作区重构方案

**当前进度：状态层和主界面拆分已完成（第 1、2、3A、3B、4、5、6 步）。**

每次开始或继续这项重构，以及同一次任务中进入下一步之前，都要重新完整阅读本文件。先对照进度表与当前代码，确认本步要搬的职责、需要保住的行为和验收条件；交付后写回实际改动、验证结果与下一步。若发现代码与方案不一致，先核实原因，并把确需调整的边界记在这里。进度以落地的代码和验证结果为准。

## 目标与范围

将 [`workspace-store.ts`](../src/store/workspace-store.ts) 拆成**一个稳定的对外入口、一个工作区状态实例、若干职责清楚的模块**。现有变量库和设置库保持原有职责。拆分完成后，维护者能从功能找到应修改的模块，例如导入角色卡去馆藏模块，切分支后变量不对去分支模块。

第一轮保留 `workspace-store.ts` 的导入路径、导出签名、状态字段和保存格式。[`AdaptiveWorkspaceApp.tsx`](../src/shell/AdaptiveWorkspaceApp.tsx) 继续使用现有入口，界面不在这次重构的范围内。兼容层、插件宿主和局域网同步也先保留现有调用方式。拆分不设行数指标，也不引入新状态管理库或另建一套持久化队列。

## 模块分工

以下模块建议放在 `src/store/workspace/`。按阶段建立必要的模块，不提前创建空文件。

| 模块 | 职责与边界 |
| --- | --- |
| `state.ts` | 放 `WorkspaceState`、初始状态和唯一的 `workspaceStore` 实例。创建状态时不启动兼容运行环境，不注册插件。 |
| `library.ts` / `library-actions.ts` | 分别管理馆藏查询与格式校验、馆藏写入。馆藏操作包含角色卡、世界书、预设和玩家资料。文件解析复用 `core/character-import.ts` 与 `pipeline/normalizer.ts`。删除角色涉及关联存档或图库时，调用现有会话与保存流程。 |
| `sessions.ts` | 管新建会话、切换角色、打开旧档、导入导出和夜灯畅谈的会话管理。`chat-archives.ts` 继续读写档案，`core/story-save.ts` 继续处理存档文件。 |
| `branches.ts` | 管选择、重试分支及分支检查点的保存与恢复。复用 `chat-tree.ts`、`branch-state.ts` 和 `branch-runtime.ts`；保持剧情节点、候选回复、变量、世界书计时与草稿的对应关系。 |
| `prompt.ts` | 把当前会话转换为提示词管线所需的输入，管理提示词预览和模板预加载。预览与生成继续共享组装规则。 |
| `message-display.ts` | 管正文格式、流式显示投影和作者组件定位。模板渲染结果和缓存失效由同一处维护，显示模块读取它们。 |
| `generation.ts` | 管发送、停止、重生成和生成状态，协调模型请求、插件、作者脚本与 MVU 结算。夜灯畅谈和角色扮演保留各自的流程。 |
| `storage.ts` / `hydrate.ts` | 分别管理工作区快照的字段映射与保存、启动时的读取和兼容处理。复用 `persistence.ts` 的队列、事务及回滚机制。 |
| `runtime.ts` | 负责接上原生故事接口、扩展和变量访问等跨模块能力。注册只做一次，保留现有启动时机。 |

`workspace-store.ts` 逐步变成对外入口，负责导出与必要的初始化连接。内部模块直接依赖具体模块，不反向引用旧入口；查询和转换尽量接收明确的输入，不为了取一个字段来回依赖多个模块。现有直接写 `workspaceStore.setState()` 的调用，等对应模块稳定后再逐个收拢到有名字的业务操作，避免一次改动所有调用者。

## 实施顺序

### 1. 馆藏导入与只读查询 · 低风险

- 从 `importAssetFile` 提取文件识别和格式校验，复用已有 PNG、JSON 解析器。按现有顺序区分快捷回复、预设、世界书与 JSON 角色卡；`importStoryCharacter` 继续保持只接受角色卡的规则。
- 迁出不触发保存或事件的馆藏查询。导入入口先保留原有的同名与 ID 冲突判断、随卡世界书处理、快捷回复全局绑定及分支各自的保存时机。预设导入后不自动替换当前会话正在使用的预设。
- 收尾标准：外部入口与调用方式一致，没有改界面或持久化；后续修改格式识别不再需要翻生成、分支和存档代码。

### 2. 提示词与消息显示 · 中风险

- 先迁出提示词输入组装和消息显示函数，再一起迁移模板缓存及其失效规则。正式生成、提示词预览和兼容辅助生成继续使用原有输入语义。
- 保留切换会话、预设与正则后刷新的条件及顺序。保留历史楼层的正文处理、流式显示和作者组件定位，避免只有最近消息走完整渲染流程。
- 收尾标准：缓存只有一个维护者；对外查询接口及刷新时机不变。

### 3A. 存档与会话 · 高风险

- 迁移会话的新建、切换、存档导入导出与恢复。保持 `workspace_assets`、`workspace_snapshot`、`chat_archive_index` 和 `chat_archive:*` 的键及格式；不做存储迁移。
- 保留恢复旧档的顺序：准备完整候选状态，成功写盘，再一起发布会话、变量与设置。延后写入和后续重放、旧存档回退、失败处理及兼容事件都沿用原流程。
- 收尾标准：新会话、切角色、打开旧档和导入档案各有明确入口；存档格式与关键保存顺序不变。

### 3B. 分支与检查点 · 高风险

- 迁移检查点捕获与恢复、分支选择和重试。保持消息与候选回复标识、分支检查点结构，以及旧档缺少分支检查点时的恢复方式。
- 保留分支激活时的消息路径、候选回复、变量、世界书计时、模板状态和输入草稿的恢复顺序，及兼容环境重启、分支事件、提示词刷新的触发时机。
- 收尾标准：分支逻辑有单一归属；不会因拆分让新路线的消息和旧路线的变量被混用。

### 4. 生成流程 · 最高风险

- 把 `sendUserMessageAndGenerate` 按准备输入、接收并显示回复、结算及保存分段。共用现有的取消与忙碌状态管理，保留角色扮演和夜灯畅谈各自的流程。
- 保留停止和失败时的收尾、占位回复处理、MVU 结算及作者事件顺序。插件 `replySaved` 继续在对应回复保存成功后通知。此阶段不顺手修改模型请求参数、流式策略或结算规则。
- 收尾标准：能分别定位生成准备、流式显示和结算保存逻辑；调用方不用改变发送、停止或重试方式。

状态、快照及运行接口模块随相应阶段迁移；没有独立职责或暂时需要一起运行的代码可以继续留在入口，避免为了移动代码就新造一层接口。

### 5. 收拢外部状态写入

- 将兼容层的馆藏、世界书绑定、计时和生成状态写入移交给对应模块。保留请求校验、保存和刷新顺序，以及导入替换馆藏和编辑剧情内世界书的行为区别。
- 将回复配图的归属检查和写入放在同一消息操作里。原生插件的资产提交和撤销继续用原事务；局域网同步继续把工作区、变量和设置一同发布和回滚。
- 收尾标准：工作区模块外无直接调用 `workspaceStore.setState()` 或 `holdWrites()` 的地方。旧入口及导出保持兼容，不改状态字段或存档格式。

### 6. 拆分主界面

- 从 `AdaptiveWorkspaceApp.tsx` 迁出启动、馆藏、会话历史、阅读、输入和设置等界面职责。主组件继续协调跨区导航、引导、外观布局和弹窗顺序；可独立维护的界面状态跟随相应功能。
- 保持已存在的 DOM 结构、`data-guide` / `data-ti-*` 挂点及插件插槽。首页和阅读模式继续用原方式隐藏区域；不因导航卸载兼容阅读环境或重置草稿。保留等待读档、恢复会话、角色卡删除、配图和同步的原有保护。
- 收尾标准：按功能能定位界面改动；本步不做视觉改版，不修改工作区状态、存档结构或原生构建配置。

## 每步的交付和验收

一批只迁移一类职责，保持能独立交付和回退。每步完成后运行 `npm run typecheck` 和 `npm run build`，并对照改动前后的导出、保存调用、关键 `await` 与兼容和插件事件顺序。不新增测试用例。类型检查和构建只证明代码能通过编译和打包，不能证明异步行为一致；存档、分支、生成各自单独对照，不与新功能混做。

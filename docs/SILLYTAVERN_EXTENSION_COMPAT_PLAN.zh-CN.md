# 酒馆扩展兼容实施方案：以柏宝书为首个验收对象

状态：兼容预览版已构建，尚未实机验收。插件基准为未经修改的 [柏宝书 1.3.5（`0a3a1cd`）](https://github.com/baibai-git/ST-BaiBai-Book/tree/0a3a1cdfe92bf5ff1b822b6b6588cb694090d0da)，宿主行为参照为 [SillyTavern 1.16.0（`e3b866b`）](https://github.com/SillyTavern/SillyTavern/tree/e3b866b5d2bcc7fbaa889bb926fbb567cd1ed25b)。插件 manifest 的最低版本 `1.12.13` 不代替行为参照。

剧情分支的后续实施见[柏宝书与剧情分支兼容方案](./BAIBAIBOOK_BRANCH_COMPAT_PLAN.zh-CN.md)。专项计划涵盖共用楼层的摘要隔离、切线前保存、向量索引及缓存、带记忆续聊，不代表这些行为已验收。

## 目标与边界

用户从现有「酒馆兼容扩展」入口安装原版柏宝书，配置好模型后，可以在角色聊天里使用自动与手动摘要、记忆注入、楼层操作、带记忆开新对话；最后再支持可选的向量召回。Windows 和 Android 交付安装包，本地网页版沿用自己的扩展加载入口。已有「夜灯畅谈」仍走自己的模型聊天路径。

**酒馆行为由兼容层负责，实际工作由 TipsyIsle 核心完成。** 分工如下：

- **兼容层**（`src/compatibility/` 与酒馆模块导出、路由适配）按 SillyTavern 的约定暴露函数和事件，负责参数与返回值、事件顺序、数据格式、页面挂点，以及把兼容 HTTP 请求转成内部调用。例如，插件调用 `saveChat()` 时，由兼容层把酒馆楼层格式转成 TipsyIsle 的消息变更。
- **TipsyIsle 核心**负责分支、消息、持久化、提示词、世界书扫描、模型连接和向量索引。需要时可以增加通用操作，例如原子提交新会话的消息与元数据；不在核心里写柏宝书特判，也不更改原生插件 SDK 的对外合同。TipsyIsle 不依赖 SillyTavern 运行。

柏宝书名字和 `bbs_*` 数据键只用于源码对照与验收，不用来决定宿主行为。柏宝库的指定 URL 属于上游协议，可以放在对应的兼容适配里。兼容范围按实际验收过的版本、平台和功能记录，能安装或加载不代表功能都能用。

| 批次 | 范围 | 用户验收后可对外确认 |
| --- | --- | --- |
| 第一批：步骤 0–4 | 摘要、注入、世界书、随分支恢复、面板、带数据开启新聊天 | 已验证柏宝书 1.3.5 的摘要与记忆续聊；向量召回暂未支持。 |
| 第二批：步骤 5 | 柏宝库协议、本地向量索引、跨对话记忆快照 | 已验证柏宝书 1.3.5 的向量召回，以及兼容表列出的配置。 |

## 交付与验收分工

- **开发交付**：以插件和参照版本的源码为准补齐功能，按方案核对实现是否完整，跑构建及必要的静态检查。交付 Windows、Android 可安装包，附插件安装与启用入口、需要的模型配置和已知限制。复用现有运行与存储路径，不另起性能测试、测试工程或重复的实机走查，也不要求为交付调用真实模型。
- **用户验收**：下面各节的「用户验收」用于你用自己的设备、角色卡、存档和模型确认体验。性能也由你决定是否测、怎么测。开发过程中发现的功能缺口由开发方补齐，不把修复留给用户。
- **状态记录**：「实现完成」表示该阶段所列行为均已实现、完成源码核对和对应构建；「用户已验收」单独记录真实使用结果、版本和平台。未实测的项目不标成已验证，也不以构建成功替代功能交付。

## 0. 固定基线和安装路径

- [x] 固定参照版 SillyTavern 的版本与源码。插件通过扩展管理安装 `https://github.com/baibai-git/ST-BaiBai-Book`；基准包自带 `dist/index.js?ver=1.3.5`，不要求用户编译插件。第一批按关闭向量交付。
- [x] 核心路径：`getContext()` / `eventSource` 驱动摘要，`generateRaw()` 调用主模型，`saveChat()` 写回楼层，`setExtensionPrompt()` 注入；独立摘要模型走聊天补全 HTTP。世界书动态导入优先取 `checkWorldInfo()`，缺失时可降级到 `getWorldInfoPrompt()`。`doNewChat()` 用于续聊，顶栏和输入区入口、柏宝库 HTTP 属于可选能力。
- [x] 对照 [Web 加载器](../server/extensions.mjs)、[安装版加载器](../src/compatibility/native-extension-files.ts) 和[扩展目录](../src/compatibility/extension-host.ts)。保留入口查询参数和相对资源路径，补充入口与拦截器缺失提示。启停后使用现有「重新载入运行环境」替换整个 iframe，旧监听器和注入随旧页面销毁。
- [x] `USER_MESSAGE_RENDERED`／`GENERATION_STARTED` 启动摘要，生成拦截器随后协调是否放行；楼层摘要写在 `chat[i].extra`，聊天级数据通过 `chatMetadata` 保存，记忆写入对应的 `setExtensionPrompt()` 槽位后进入主模型请求。

用户验收：通过现有入口安装并启用原版扩展，确认能打开设置；停用后不再触发摘要或注入。

## 1. 跑通摘要 → 写回 → 下一轮注入

复用 [兼容上下文和生成拦截](../src/compatibility/frame-entry.ts)、[请求适配](../src/compatibility/host-fetch.ts)、[宿主调用入口](../src/compatibility/workspace-host.ts)、[生成流程](../src/store/workspace/generation.ts) 和[现有消息写回](../src/store/workspace/message-edits.ts)。先对照插件调用和现有实现，再补行为缺口。

- [ ] 对齐 `MESSAGE_SENT`、`USER_MESSAGE_RENDERED`、`GENERATION_STARTED`、生成拦截、注入读取、消息更新与终止/完成事件的顺序和参数，覆盖正常发送、重新生成、翻页、删楼和主动停止。参照版中摘要触发早于生成拦截；拦截中止时，主模型不应再收到那一轮请求，插件插入的提示楼仍要能保存。
- [ ] 对齐 `setExtensionPrompt()` 的同键覆盖、空值移除、插入深度、角色和扫描选项，并接入主模型请求的组装流程。让 `/hide`、`/unhide` 的楼层范围和 `/sendas` 插入的提示楼按约定反映在显示、提示词和存档里。
- [ ] 让 `generateRaw({ prompt, responseLength })` 只发送插件给定的消息，避免摘要再次触发故事生成拦截。支持跟随主模型，以及插件通过酒馆兼容 HTTP 路由配置的独立摘要模型。模型请求沿用现有宿主桥接。
- [ ] 保持 `chatMetadata`、`chat[i].extra` 和当前 swipe 正文的保存语义。把写回绑定到原会话、原路线版本、消息 ID 和回复版本；优先复用现有 `branchEpoch`、快照与写回校验。旧请求完成时，不能把摘要、隐藏状态或注入留在已经切换的新路线。现有实现能处理普通楼层的增量修改，但不支持结构改动，留到步骤 3。
- [ ] 在诊断信息里区分回调异常、超时和主动中止。不要把所有兼容调用的超时统一调大，也不要用额外一次模型调用替代现有摘要结果。

用户验收：原版插件能做自动摘要和手动摘要，下一轮能用上摘要，关闭并重启应用后仍能恢复；分支切换、重新生成或删楼后，摘要不会跨路线串写。

## 2. 补世界书扫描合同

现有世界书接口支持读写，缺的是「按插件给出的文本扫描，并返回条目」的对外合同。复用 [现有扫描器](../src/pipeline/lorebook-scanner.ts)、[世界书宿主](../src/compatibility/worldbook-host.ts) 与[模块导出适配](../server/extension-modules.mjs)。

- [ ] 在上下文提供 `getWorldInfoNames()` 和 `getWorldInfoPrompt()`，在 `/scripts/world-info.js` 提供 `checkWorldInfo()`。按参照版确认消息顺序、`maxContext` 的预算含义和 `globalScanData` 的有效字段，避免把上游的最大上下文长度直接当作世界书条目的独立预算。
- [ ] `checkWorldInfo()` 返回可按书名与条目名过滤的对象集合，保留 `world`、`uid`、`comment`、`content`、`order`、`position`、`depth` 等调用所需字段。`getWorldInfoPrompt()` 按约定返回角色前后、作者注、深度条目等对应内容。不要只返回一段拼好的文本就宣称完成。
- [ ] 使用当前角色和路线的有效绑定。只读扫描允许计算激活结果，但不推进黏性、冷却和延迟计数，不提交扫描后的世界书状态；摘要请求也不应凭扫描动作改动主对话。涉及 EJS 时核对原插件调用已有 `EjsTemplate` 的路径，避免宿主与插件重复执行一次模板。

用户验收：常驻项、关键词触发和深度条目按设置生效；同名条目和「整本排除」按指定书与条目区分。连续发起摘要时，主对话的世界书定时状态保持原样。

## 3. 做通「带记忆开新对话」

原插件在 `await doNewChat({ deleteCurrentChat: false })` 之后，仍在同一段 JavaScript 里调用 `getContext()`，用 `push()` 和 `splice()` 写入种子摘要和最近正文。普通 `saveChat()` 继续拒绝直接改动聊天结构；由新会话交接提供一次性开场提交。见[上游搬运流程](https://github.com/baibai-git/ST-BaiBai-Book/blob/0a3a1cdfe92bf5ff1b822b6b6588cb694090d0da/src/memory/carryover.ts) 与[会话模块](../src/store/workspace/sessions.ts)。

- [ ] 从 `/script.js` 暴露 `doNewChat()`；先实现该插件实际使用的 `deleteCurrentChat: false`。用现有归档与新建逻辑保留源聊天，`await` 返回时，调用方必须能读到准确的新聊天 ID、开场和 metadata。核对旧扩展页面与新会话的连接交接，考虑只对发起切换的调用提供短范围的交接；普通旧会话消息仍不能写到新页面。
- [ ] 为刚创建的角色聊天提供一次结构提交：允许追加最近楼层、建立或更新种子摘要锚点，以及清理插件搬运时会替换的开场内容。把传入的楼层形状转成宿主自己的消息 ID、父子关系和回复版本，保留插件附加数据。用现有持久化事务一并提交消息与元数据，防止写到一半留下部分记录。普通活动分支的结构写入限制保持原样。
- [ ] 对照 `saveChat()`、`saveMetadata()`、`reloadCurrentChat()` 和 `CHAT_CHANGED` 的时机，确认调用者不会在第一次 `await` 后就被卸载，也不会重复归档、重复插楼。保存失败时，旧会话仍可恢复，新会话保留可解释的状态，不能把半次搬运当成成功。

用户验收：用有开场或空开场的卡带记忆开新聊，旧聊天继续可用，新聊天重启后保留最近正文、种子摘要和插件携带的状态；旧会话中还在运行的异步操作不能覆盖这些数据。向量快照归步骤 5。

## 4. 接好扩展面板并交付第一批

- [ ] 检查扩展菜单、消息 `.mes[mesid]`、`#chat`、输入框及相关事件现有的实现。柏宝书的快捷按钮还会查找 `#send_form`，可选顶栏按钮会找 `#top-settings-holder` 和 `#persona-management-button`；根据实际行为补通用挂点或把操作桥接到现有入口。保留插件对楼层挂载、滚出视口再挂载和销毁的预期。
- [ ] 在 [兼容聊天容器](../src/compatibility/CompatibilityChat.tsx) 中处理依赖真实楼层 DOM 的扩展展示。当用户确实使用这类面板，保证它能出现在当前楼层；没有此依赖的对话保留现有虚拟列表。也要核对普通卡用原生列表时，扩展菜单能否打开插件自己的面板。
- [ ] 将面板接入现有桌面与移动端入口，处理 Android 上的面板滚动、输入焦点与返回操作。交付 Windows 与 Android 安装包，说明本地网页版的使用入口和当前已知限制。

用户验收：以常用角色卡和存档确认设置能打开、楼层面板滚出再回来仍可用，以及前面列出的摘要、分支与记忆续聊功能。Android 可顺手确认滚动、输入和返回；原有角色卡和夜灯聊天应能照常打开与生成。

## 5. 接入柏宝库协议，交付向量召回

在兼容层把柏宝库的指定协议映射到 TipsyIsle 的索引能力。若现有索引无法满足查询或快照语义，在核心补相应的通用索引操作。Android 安装版的本地实现不应依赖额外启动一套 SillyTavern 服务。

| 协议能力 | 实现时必须核对 |
| --- | --- |
| `GET /status` | 索引可用才报告 `driver.available`。 |
| `vec/upsert`、`vec/update-payload` | 保留库、scope、叶子 ID 和两个内容哈希；支持只更新正文或时间，不重新算嵌入。 |
| `vec/search` | 支持多 scope、多查询向量、`topK`、排除叶子和命中来源；核对分数、`queryIndex`、排序及重复结果规则。 |
| `vec/delete`、`vec/clear-scope`、`vec/reconcile`、`vec/stats` | 确认删除范围、对账结果与计数语义。区分缺失向量和仅正文过期。 |
| `vec/bundle/create` | 用源聊天生成可重用的冻结快照，保留原返回的 `hash`、`scope`、`copied`、`reused` 语义；源聊天后续编辑不应改变已冻结的快照。 |

- [ ] 对照 [上游协议客户端](https://github.com/baibai-git/ST-BaiBai-Book/blob/0a3a1cdfe92bf5ff1b822b6b6588cb694090d0da/src/api/baibaoku.ts)，核对 HTTP 方法、JSON 包装、错误码和 Float32 小端向量格式。路由通过现有兼容请求桥接；复用[原生索引接口](../packages/plugin-sdk/index.d.ts) 的底层能力，不修改对外的原生 SDK 合同来迁就旧协议。
- [ ] 保留插件的独立嵌入和重排模型配置，并按请求来源接好对应路径。索引状态和模型请求失败应分别反馈，不应默默把数据改送其他模型。交付时写明如何配置所需端点。
- [ ] 插件按对话和 bundle 查找历史，TipsyIsle 同一个对话还可能包含多条路线。根据已捕获的路线与回复版本限定写入和读取，把插件声明的库和 scope 映射到内部命名空间。用户从 A 切到 B 后，B 的对账不能清掉 A 的数据；重新进入 A 也不能读到只在 B 出现的叶子。显式继承的 bundle 可以跨对话使用。

用户验收：用配置好的模型确认能建索引、召回旧楼并注入；编辑或删楼后索引随之更新，跨对话继承的快照不受源会话后续编辑影响。关闭向量或索引不可用时，第一批的摘要功能仍可用。

## 预览版使用入口

本地安装包在 `releases/extension-compat-preview/`，包括 Windows x64 安装包和 Android ARM64 APK。预览版沿用应用版本 `1.1.0`。TypeScript 类型检查、Web 生产构建和两端打包均通过；未做实机走查、模型调用或性能跑分。

1. 在「设置 → 插件 → 酒馆兼容扩展」输入 `https://github.com/baibai-git/ST-BaiBai-Book` 安装原版插件，保持启用，再点「重新载入运行环境」。本地网页版也从该处安装，需要启动本地网关与兼容服务。
2. 打开角色聊天，在输入框附近的「更多 → 快捷功能」打开柏宝书。先用主模型或独立的 OpenAI 兼容摘要接口，体验手动摘要、自动摘要、记忆注入与续聊。要看楼中面板，开启柏宝书的楼中面板设置，以及 TipsyIsle 快捷功能里的「楼层扩展」。关掉后，普通角色继续使用虚拟阅读列表。
3. 要试向量召回，在柏宝书里开启向量记忆并配置嵌入模型和查询重写渠道；重排模型可选。插件照常请求这些模型，服务端点须允许应用内网页发起跨域请求。向量索引保存在本机，不用另开柏宝库或 SillyTavern 服务。

向量索引和冻结包是本机派生数据，不随现有局域网同步搬运。当前范围针对柏宝书 1.3.5 调用的接口；其他插件、更新后的版本、Android 交互和实际模型响应仍需验收。
